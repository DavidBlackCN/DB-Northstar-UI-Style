# Northstar UI

使用这套风格创造或整合清爽、柔和、中性且带轻微技术感的界面。将 Northstar 视为默认视觉语言，而不是改写产品信息架构、组件库、路由或交互模型的理由。

## 先理解，再落地

开始前检查页面结构、现有 Token、组件库、路由状态、Portal 浮层、响应式断点、图标体系和已有动效。动态界面同时检查真实 DOM、计算样式与交互结果，不能只凭 class 名或截图推断行为。

优先复用目标应用的原生组件、语义状态和公开主题接口。参考页面与目标产品冲突时，优先保留产品功能、信息架构、操作效率和可访问性，只迁移兼容的视觉原则。

## 决策边界

### 必须遵守

- 用语义 Token 成对维护浅色与深色，不做简单反色；至少覆盖背景、表面、浮层、三档文字、边界、焦点、信息、成功、警告、危险、选中与禁用。
- 将状态绑定到真实交互目标或状态属性。区分短暂 hover 与持久 selected；重要状态不能只依赖颜色。
- 让 Portal 浮层作为独立层级单独处理和验证，不能假设继承页面容器样式。
- 验收以浏览器中的计算样式、几何、截图和真实交互结果为准；无法触发的状态必须明确记录。
- 为关键动效提供 `prefers-reduced-motion` 静态退化。

### Northstar 默认值

- 内容优先，低饱和、轻边界、少阴影；浅色用暖象牙白，深色用多层深灰。避免纯白铺底、纯黑、夸张渐变、泛滥大圆角和装饰性阴影。
- 使用 Sans Serif 承担长阅读，用 Maple Mono 提供技术性格；不要将长中文段落和正文改为等宽字体。
- 常规分隔保持低对比 1px；可选择、聚焦或激活的带边框控件使用一层清晰的 2px 边界，不再外套第二层边框或阴影。
- 星点 / 云朵主题开关是可选的 Northstar 表现；仅在适合且已有主题切换时采用，不是所有页面的必备功能。

### 依据产品决定

- 用户品牌、既有设计系统、组件 API、可访问性要求和技术栈优先于默认色值或组件外观。
- 根据内容类型决定密度、容器宽度和响应式重排；不要以无差别缩小字体或隐藏关键操作解决空间问题。
- 对 Canvas、WebGL、编辑器、终端和图表使用其公开主题 / 字体 API；容器 CSS 不能替代实际渲染器配置。

## 实施方法

1. 先定位现有语义 Token 与状态接口；以变量、主题对象或组件库主题层实现视觉变化，避免散落硬编码色值。
2. 为交互组件覆盖 default、hover、active、focus-visible、selected、disabled 与 loading；为数据状态覆盖 success、warning、danger、idle、empty 与 error。检查透明度、滤镜、过渡和关键帧不会削弱新状态。
3. 以语义类、状态属性、明确作用域和层叠顺序处理 CSS 覆盖。避免无目标地提高选择器或使用 `!important`；动态补丁必须幂等、可卸载且范围受限。
4. 将浮层、固定格式组件与非 DOM 渲染面视作单独验收对象。为动态数字、Badge、工具栏和表格预留稳定尺寸，避免状态变化造成布局跳动。
5. 在真实浏览器中切换主题、状态、视口和输入方式后再交付。具体矩阵见 [验证参考](references/validation.md)。

## 按需参考

- 准备验收、处理浮层 / 非 DOM 渲染、响应式或动态状态时，读取 [浏览器验证参考](references/validation.md)。
- 设计页面密度、内容宽度或移动端重排时，读取 [页面模式参考](references/page-patterns.md)。
- 需要实际的 Northstar 结构和代码表达时，读取 [示例索引](references/examples/index.md)，且只打开与任务相关的一个页面。示例是参考快照，不是必须整体复制的模板。

## 交付

说明保留了哪些产品既有约束、采用了哪些 Northstar 默认值，以及浏览器实际验证过的主题、视口、状态和交互。不要将未验证的推断表述为已完成验收。
